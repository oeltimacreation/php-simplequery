# 0.8 development review

Date: 2026-09-18. This records the bounded development decisions, candidate
certification, and release finalization for `0.8.0`. Source identities refer to
commits on `feature/0.8-candidate`; generated reports remain ignored.

## Scope and decisions

The 0.8 plan targeted worker lifecycle reliability and interoperability with
the first internal FrankenPHP worker-mode consumer. Accepted outcomes:

- **D1/D2** — `isClosed()`, `isReusable()`, and terminal `discard()` inspect
  local wrapper state and never ping, reconnect, or replay; strict `close()`
  remains ([ADR-024](../adr/024-explicit-connection-lifecycle.md)).
- **D3** — connection-construction failures expose normalized
  `ConnectionException` evidence (`operation`, `sqlState`, `driverCode`,
  `driver`, `connectionLabel`) without retaining the raw PDO exception,
  driver message, or trace
  ([ADR-009](../adr/009-exception-evidence-and-redaction.md) amendment).
- **D4/OBS-1** — lifecycle counters remain application-owned; no lifecycle
  observer ships in `0.8.0`
  ([ADR-010](../adr/010-non-interfering-observation.md) unchanged).
- **D5** — the transaction ownership guard and inspections are retained,
  measured at tens of microseconds per transaction on direct engines
  ([ADR-008](../adr/008-transaction-ownership-and-savepoints.md) amendment).
- `min()`/`max()` now describe and validate the `int|float|string|null` scalar
  union and throw `QueryExecutionException` for an unsupported driver scalar
  ([ADR-006](../adr/006-results-and-write-returns.md) amendment).

## Security review

Reviewed the complete source diff from `v0.7.0` against the
[security checklist](../maintainers/security-review-checklist.md). Values
remain bound parameters; no identifier interpolation, raw-SQL widening,
transparent reconnect/retry/replay, or hidden LOB materialization was added.
The diff adds local lifecycle inspection, normalized construction diagnostics
with `#[SensitiveParameter]` on the DSN, a closed-connection cursor guard, and
shared malformed-`errorInfo` normalization. The raw PDO exception chain stays
unretained for construction failures; query execution keeps its existing
diagnostics. Synthetic probes and documentation diffs were reviewed for
credentials, private hostnames, and customer data; none were added.

## Remote CI, code health and pending release evidence

Pull request [#8](https://github.com/oeltimacreation/php-simplequery/pull/8)
ran the required CI matrix on `e171c1d`
([run 35351046356](https://github.com/oeltimacreation/php-simplequery/actions/runs/35351046356)):
all twelve jobs passed — PHP 8.2–8.5 SQLite compatibility, lowest
dependencies, actual SQLite 3.39.2, artifact-installed no-dev consumers,
quality gates, Xdebug branch/path coverage, minimum/current direct probes, and
the both-order `v0.7.0` benchmark comparison. External CodeScene review
initially failed on two hotspot declines and six new files; behavior-preserving
guard and extraction refactors plus documented narrow rule exceptions resolved
the findings, and CodeScene passes on `e171c1d`. The default-branch merge
commit `4fe29cb` passed the twelve-job CI matrix
([run 35351314065](https://github.com/oeltimacreation/php-simplequery/actions/runs/35351314065)),
and the scheduled proxy workflow passed on the `v0.8.0` tag
([run 35351327168](https://github.com/oeltimacreation/php-simplequery/actions/runs/35351327168)).

The tag CI benchmark job
([run 35351327099](https://github.com/oeltimacreation/php-simplequery/actions/runs/35351327099))
flagged a repeatable candidate cost on streaming-cursor operations. The first
attempt blocked `cursor_exhaustion/simplequery_object_cursor` and
`result_memory_normal/simplequery_streaming_cursor`; a rerun blocked
`result_memory_high/simplequery_streaming_cursor`. The same tree passed three
candidate runs and the default-branch run; the tag runs had narrower
identical-source ranges. Local A/B measurement with and without the W1
per-row discarded-connection guard (`Cursor::rows` checking
`Connection::isClosed()` before every fetch) attributes roughly +0.02–0.04 ms
per small cursor operation (about 6–9%) and about +0.9 ms on the
high-cardinality streaming scenario to that guard. The guard preserves the
documented "advanced after discard fails before another fetch" behavior and is
retained in `0.8.0`; a cheaper per-row check is a candidate post-release
correction.

The following remain application- or operator-owned and were not exercised
here: database-backed consumer endpoints, response payloads, authorization,
and HTTP error-envelope redaction (the consumer database is not disposable;
database-free classic and single-worker responses matched `0.7.0`); staged
consumer rollout, worker restart, and rollback; and production proxy settings.
None of these is a library support claim.
