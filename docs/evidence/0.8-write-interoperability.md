# 0.8 write interoperability validation

Date: 2026-09-18. Scope: W4 library fixtures, direct-engine write probes, and
consumer static-analysis adoption, not a release certification or a production
deployment claim.

## Tested source

The tested candidate is `feature/0.8-candidate` at `de6af47`, which includes
the W4 test/fixture commits `35af741` (lazy injection, write returns, shapes,
answer-save races), `f2d8dc5` (public-consumer static analysis and lane
coverage), `bc11ed4` (vendor-writes probe), and `de6af47` (`min()`/`max()`
scalar validation and ADR-006 amendment).

The private consumer checkout remains read-only; adoption checks run against a
temporary copy in the [0.8 candidate rehearsal evidence](0.8-worker-rehearsal.md).

## Reproduction

```bash
composer check
composer test -- --filter 'LazyInjection|LegacyWriteReturn|QueryShapeExecution|AnswerSaveRace|AggregateScalarValidation'
php tools/database-probes/vendor-writes.php mariadb
php tools/database-probes/vendor-writes.php mysql
bash tools/database-probes/run-services.sh
```

The probe creates a randomized `simplequery_vendor_writes_*` table, drops it in
`finally`, and uses only disposable fixtures. The service runner executes it in
all four prepare/buffering profiles on the direct engines.

## Direct-engine observations

The vendor-writes probe passed in all four prepare/buffering profiles for both
engines with identical observations (MariaDB 11.8.8, MySQL 8.0.46, native
buffered shown):

| Observation | Result |
| --- | --- |
| `insertGetId()` increments | `'1'`, `'2'`, then increasing on the same session |
| Session identity around write and ID read | Stable, `isReusable()` true |
| Duplicate `insert()` | `23000` / `1062` |
| `INSERT IGNORE` duplicate | `0` affected rows; `lastInsertId()` `'0'` |
| Upsert existing row | `2` affected rows; `lastInsertId()` `'1'` (not a reliable row ID) |
| Upsert new row | `1` affected row; generated ID `7` (gaps after failed/ignored writes) |
| `id = LAST_INSERT_ID(id)` upsert | Returns the existing row ID `1` |
| Batch then next ID | `2` affected rows; next ID increases |
| Bind-count boundary | 5,000 values execute; 65,536 placeholders fail with `1390` under native prepares and complete under emulated prepares |
| Payload round trip | `max_allowed_packet` recorded; ~320 KiB row preserved exactly |
| Two-session lock ownership | Second owner blocked with `1205`; committed state visible after release |

The observations are engine- and profile-specific evidence, not a portable
contract. Generated IDs are not contiguous, and an upsert is not an
idempotency mechanism.

## Validation

- `composer check` passed after the additions (test counts recorded with the
  W4 plan update); PHPStan level 9, PHPCS, the public API manifest, docs,
  examples, release consistency, and repository verification are included.
- Coverage passed after the `min()`/`max()` source change: 96.20% line overall
  and 97.33% compiler line; 92.88% branch overall and 92.99% compiler branch.
- The public-consumer lane passes with the extended assertions and the two
  additional standalone fixtures.
- The full service matrix passed with the vendor-writes probe included:
  83 reports (1,080 passed and 289 observed outcomes, no failed observations)
  across MariaDB 11.8.8, MySQL 8.0.46, ProxySQL 3.0.1, and MaxScale
  23.02.17-2 in all four prepare/buffering profiles. The eight vendor-writes
  reports each passed 12 observations; the bind-count boundary failed with
  `1390` under native prepares and completed under emulated prepares on both
  engines.
- A temporary copy of the private consumer passes its unchanged PHPStan level 5
  against the candidate package, and the migration slice recorded in the
  [candidate rehearsal evidence](0.8-worker-rehearsal.md) passes a live holder
  smoke on both direct engines.

`min()` and `max()` now share the validated `int|float|string|null` contract of
`sum()`/`average()`; the reviewed public API manifest diff contains only those
two return types, and [ADR-006](../adr/006-results-and-write-returns.md) records
the amendment.

## Limits and remaining work

- The private consumer's development endpoints, response payloads, and
  authorization/race behavior were not executed; its checkout, database,
  credentials, and business flows remain outside this record. Consumer
  endpoint checks, staged rollout, and rollback remain adoption work.
- The write probes cover MariaDB/MySQL only. SQLite execution tests establish
  library behavior, not vendor-ID or lock behavior; proxy write-routing was not
  re-qualified for these shapes.
- No supported engine, floor, or public feature is added; upsert, ignore, and
  chunking remain application-owned raw SQL or application loops.
