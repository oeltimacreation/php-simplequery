# 0.7 development review

Date: 2026-09-11. This records bounded development decisions, not release
certification. Source identities below refer to local commits on
`feature/0.7-candidate`; generated reports remain ignored.

## Raw binding normalization

Accepted one internal ordered-list validation and `Binding::fromValue()` mapping
in `InputNormalizer`, called by `RawQuery` and `RawExpression`. Callers retain
their distinct list diagnostics and empty-SQL validation order. `CompiledQuery`
member/concrete-type precedence remains separate. Focused mixed-invalid-input
regressions and `composer check` passed; the public manifest is unchanged.

Compared the candidate containing this record against `f987aa0` using the same
current harness, PHP 8.4.24, SQLite 3.45.1, disabled Xdebug/PCOV instrumentation,
three warmups and nine samples. Five identical-source noise runs preceded both
source orders of `benchmarks/compare.php --suite=ci --allow-review`. All 36
scenario correctness digests matched. No actionable regression repeated in
both orders. Generated reports are under `benchmarks/results/normalization/`.

One-binding observer-off operations changed 1.301408 → 1.277627 ms in baseline-
first order and 1.293512 → 1.311145 ms in candidate-first order. Fifty-binding
observer-off operations changed 17.089096 → 17.650783 ms and 17.124738 →
17.287709 ms respectively. These are whole sampled workload times, not time per
query. The extraction removes duplicated rules; no speedup is claimed.

The host was not reserved exclusively for timing. Noise controls showed material
variance, including compile-only control movement; one-order hydration/result
signals did not reproduce. Final v0.6.0 certification must remeasure controls.

Reproduction: install the reference commit in a detached worktree, run
`benchmarks/noise.php --suite=ci --iterations=9 --warmups=3 --runs=5`, then
`benchmarks/compare.php --suite=ci --iterations=9 --warmups=3` with that
worktree's `--baseline-autoload`, the generated `--noise-report`, and each
`--source-order=baseline-first` / `--source-order=candidate-first`.

## Associative row validation

Disposition: retain local validation. Reviewed eager/first validation in
`Executor` and cursor validation in `Cursor`, plus `AssociativeHydrationTest`
and `CursorFailureTest`. Both reject non-array rows and numeric keys, but cursor
validation must construct cursor-context failures and participate in its own
fetch/finalization lifecycle. A shared helper would require passing an error
factory or contextual connection/query state on every row to eliminate two
small loops. The extraction does not sufficiently simplify these ownership
boundaries to justify new dispatch. No alternate implementation is retained and
no performance benefit is claimed.

The normalization comparison above exercised existing narrow/wide hydration,
first-row and cursor controls with matching digests. It is a characterization of
the retained implementation, not a benchmark of an unimplemented validator.
Existing focused hydration/cursor failure tests passed. Reopen only with a
concrete simpler design or new workload evidence; no new public validator exists.
