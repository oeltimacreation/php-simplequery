# `0.2.0` associative hydration experiment

Date: 2026-07-26

Baseline: `v0.1.0` / `16c59bf`

Candidate implementation: `8f90f93` (`perf: reduce associative hydration
memory`)

Decision: merge the one-pass associative hydration and no-copy associative
cursor changes. All hard acceptance gates passed in both source execution
orders.

## Method

The finalized schema-version-2 harness ran each mode in a fresh PHP process
against an identical 100,000-row SQLite fixture. Each process completed setup
before measurement, performed two warm-ups, then recorded seven correctness-
gated samples. Xdebug and PCOV were disabled for accepted timing and memory
measurements.

The comparison was run twice, first as baseline/candidate and then as
candidate/baseline:

```bash
php benchmarks/compare.php \
  --suite=hydration-experiment \
  --baseline-autoload=/path/to/v0.1.0/vendor/autoload.php \
  --candidate-autoload=vendor/autoload.php \
  --profile=reference --iterations=7 --warmups=2 \
  --source-order=baseline-first

php benchmarks/compare.php \
  --suite=hydration-experiment \
  --baseline-autoload=/path/to/v0.1.0/vendor/autoload.php \
  --candidate-autoload=vendor/autoload.php \
  --profile=reference --iterations=7 --warmups=2 \
  --source-order=candidate-first
```

The workstation matched the accepted audit environment: Ubuntu 24.04.4,
Intel Core i5-13400, PHP 8.4.23 NTS, and SQLite 3.45.1. Absolute timings are
workstation evidence; same-run ratios and correctness determine acceptance.

## Gate decision

- Associative full-result PHP peak fell from 116 MiB to 78–80 MiB. The
  candidate was 1.00–1.03× the same-run 78 MiB direct-PDO peak, passing the
  hard 1.30× gate.
- Associative median time improved by 19.6–20.8%. Its same-run direct-PDO time
  ratio was 1.58–1.62×, so the aspirational 1.50× goal was not reached; this is
  not a blocker when the hard memory and correctness gates pass.
- Object hydration changed by -1.6% and -0.4%. Associative cursor time improved
  by 9.8–10.3%. Object cursor time changed by +0.4% and -0.6%. No comparison
  introduced a median regression greater than 10%.
- Focused controlled tests retain non-array row rejection, non-string key
  rejection, PDO failure translation, observer failure reporting, and
  statement cleanup. The existing cursor failure/quarantine matrix also
  remains green.

The implementation therefore replaces bulk associative `fetchAll()` plus a
second complete result copy with a validated `fetch()` loop that constructs
only the final list. The associative cursor validates the fetched row in place
and yields that row without a redundant key/value copy. Public API and return
contracts are unchanged.

## Observer parameter-type profile

The maintained observer benchmark was extended to 1, 10, and 50 bindings with
1,000 calls per sample. Seven-sample medians were:

| Bindings | Observer off | No-op observer | Delta/call | Relative overhead |
|---:|---:|---:|---:|---:|
| 1 | 2.783 ms | 3.425 ms | 0.641 µs | 23.05% |
| 10 | 9.225 ms | 10.149 ms | 0.924 µs | 10.01% |
| 50 | 41.308 ms | 42.617 ms | 1.308 µs | 3.17% |

Because the low-binding result triggered the audit's profiling condition, an
Xdebug function profile ran 10,000 observed queries with 50 bindings:

```bash
XDEBUG_MODE=profile php \
  -d xdebug.start_with_request=yes \
  -d xdebug.output_dir=/tmp/simplequery-observer-profile \
  -d xdebug.use_compression=0 \
  benchmarks/profile-observer.php --bindings=50 --rounds=10
```

The instrumented profile attributed 335.180 ms, or 6.61% of its 5,071.520 ms
total, to parameter-type `array_map()` including callbacks. `Executor::notify()`
accounted for 543.279 ms inclusive. Xdebug numbers rank work only and are not
accepted timings. The instrumentation-free sweep shows that total no-op
observation overhead is 1.308 µs per query at 50 bindings and its relative
share falls as database binding work grows. That does not justify replacing
the simple type-collection path or adding caching/state, so no observer runtime
change was made.
