# 0.8 connection lifecycle validation

Date: 2026-09-18. Scope: W1 library implementation and local qualification,
not a release certification or production deployment claim.

## Source and accepted contract

The tested candidate consists of commits `19deccf` (lifecycle API, safeguards,
tests, manifest, ADR, reference and upgrade notes), `94ebad2` (ownership guide
and executable example), and `aba8d06` (direct lifecycle probes and runner).
The decisions are recorded in
[ADR-024](../adr/024-explicit-connection-lifecycle.md).

`isClosed()` reads wrapper state; `isReusable()` inspects local eligibility but
does not prove liveness or session cleanliness. Failed PDO state inspection
quarantines the wrapper and preserves control-failure evidence. `discard()`
permanently closes the wrapper without inspection, explicit rollback, cursor
cleanup, reconnect, or statement replay. Escaped PDO references remain usable
by their owner; discard does not prove physical rollback/disconnection.

Tests verify strict close is unchanged, stale artifacts never follow a new
connection, root/nested callback completion cannot succeed after discard,
callback/control/recovery evidence survives, and advancing an outstanding
cursor fails before another fetch. Cursor cleanup failure does not replace
that primary failure. SQLite tests establish actual PDO ownership/resource
behavior; they make no network idle-expiry claim.

## Reproduction

From a development checkout with dependencies and PDO extensions installed:

```bash
composer check
composer test:coverage
composer coverage:check
composer test:coverage:branch
composer coverage:check:branch
composer probe:sqlite
composer probe:execution -- sqlite
composer probe:transaction -- sqlite
bash tools/database-probes/run-services.sh
```

The service runner starts disposable fixtures, runs behavior/execution/
transaction regression probes plus the new direct lifecycle probes, records
image digests/proxy versions, and removes its containers/network/volumes.
Generated output remains ignored under `tools/database-probes/results/`.
It is not a production test. To run just the lifecycle probe against already
started disposable direct fixtures:

```bash
php tools/database-probes/connection-lifecycle.php mariadb
php tools/database-probes/connection-lifecycle.php mysql
```

Use `PROBE_EMULATE_PREPARES=true|false` and `PROBE_BUFFERED=true|false` to select
profiles. These probes deliberately expire and kill their own sessions, use
synthetic tables, and perform an intentionally rejected connection attempt.
They change only session `wait_timeout`, never production/global settings.

## Results

Local PHP was 8.4.24 with mysqlnd 8.4.24. Line coverage used PCOV 1.0.12;
branch coverage used Xdebug 3.5.3. The package's PHP 8.2 compatibility floor
and declared engine support matrix were not changed.

| Check | Result |
| --- | --- |
| `composer check` | Passed: 670 tests, 2,007 assertions; lint/platform, both PHPStan lanes, coding standards, API manifest, docs, examples, release consistency, repository verification passed. |
| Line coverage | Passed: 95.72% overall; 97.00% compiler. |
| Branch coverage | Passed: 92.40% overall; 92.04% compiler. |
| SQLite behavior/execution/transaction probes | Passed on SQLite 3.45.1; not a new minimum-runtime qualification. |
| Current service regression matrix | Passed: MariaDB 11.8.8, MySQL 8.0.46, ProxySQL 3.0.1 and MaxScale 23.02.17-2 fixtures; native/emulated prepares × buffered/unbuffered results. |
| All service reports | 59 reports, 800 passed and 221 observed outcomes, no failed observations. Observed outcomes retain the existing engine/proxy caveats. |
| New direct lifecycle probes | Eight reports, 30 passed observations each; two idle-expiry/recovery cycles per report. |

The new probe checks fresh state, proactive replacement before the session idle
limit, actual expiry with `wait_timeout=1`, one failed write attempt without
replay, stale-query rejection, fresh session identity, successful next-unit
writes, abrupt `KILL CONNECTION` loss, failed replacement construction, later
recovery, and reconciliation of acknowledged writes. Local inspection still
returned reusable on the expired socket, demonstrating why it is not a ping.
The proactive threshold is probe-owned, not library policy.

Across all four profiles MariaDB reported `HY000` / `2006` for idle loss;
MySQL reported `HY000` / `4031`. The latter is
[`ER_CLIENT_INTERACTION_TIMEOUT`](https://dev.mysql.com/doc/mysql-errors/8.0/en/server-error-reference.html#error_er_client_interaction_timeout),
documented since MySQL 8.0.24. A consumer recognizing only 2006/2013 must not
assume it recognizes every idle disconnect. W2 will cover structured
application inspection; this change adds no portable failure classifier.

The complete public-manifest diff was reviewed: only the three accepted
`Connection` methods were added. Security review checked safe inspection
messages, preserved existing evidence policy, no credential retention for
reconnect, synthetic probe data, terminal wrapper rejection, and no implicit
transaction completion/replay. Construction exception chains remain unchanged.

## Limits and remaining work

- This run did not execute FrankenPHP/ZTS request loops, the private consumer,
  its endpoints, or a production idle incident. W3/W4 adoption and W6 rehearsal
  remain open; the SQLite example is not a worker qualification.
- The new idle/disconnect scenarios qualify direct fixtures only. Existing
  proxy regressions passed, but proxy idle recovery/replay policies need their
  own direct controls before any such claim.
- Minimum-engine fixtures, actual minimum SQLite, full PHP runtime CI, clean
  no-dev distribution certification, and performance/soak certification remain
  release gates. No performance result or expanded support promise is inferred.
- Releasing one PDO reference cannot revoke other references, and local
  inspection inherits PDO's manual-transaction tracking limits. Applications
  still own session hygiene, request pinning, cleanup, and uncertain-write
  reconciliation; W1 does not migrate the consumer automatically.
