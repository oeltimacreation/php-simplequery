# 0.8 connection failure evidence validation

Date: 2026-09-18. Scope: W2 library implementation and local qualification,
not a release certification or production deployment claim.

## Source and accepted contract

The tested candidate consists of commits `efb11e3` (normalized
`ConnectionException` evidence, shared PDO error normalization,
`SensitiveParameter` DSN, focused tests, consumer static-analysis fixture, and
public API manifest) and `20c1cfe` (ADR-009 amendment, troubleshooting matrix,
application inspection recipe, upgrade notes, and changelog). The decision is
recorded in
[ADR-009](../adr/009-exception-evidence-and-redaction.md).

`ConnectionException` construction failures expose `operation=connect`,
normalized `sqlState`/`driverCode`, `driver`, and `connectionLabel`. The raw
`PDOException`, driver message, and trace are deliberately not retained, so
`getPrevious()` stays null even though the previous release behavior also
required that. Closed-wrapper and compiler-only misuse use `operation=closed`
and `operation=compiler_only`, so applications never need to match exception
messages. Query execution keeps the previous `PDOException` for diagnostics and
now shares the same missing/malformed `errorInfo` normalization.

The library still ships no retry classifier. The application-owned inspection
recipe covers query loss, `TransactionException::connectionUnusable`, cursor
cleanup quarantine, and the separation between eviction and replay eligibility.

## Reproduction

From a development checkout with dependencies and PDO extensions installed:

```bash
composer check
composer test:coverage
composer coverage:check
composer test:coverage:branch
composer coverage:check:branch
composer probe:sqlite
composer probe:execution -- sqlite
composer probe:transaction -- sqlite
```

## Results

Local PHP was 8.4.24 with mysqlnd 8.4.24. Line coverage used PCOV 1.0.12;
branch coverage used Xdebug 3.5.3. The package's PHP 8.2 compatibility floor
and declared engine support matrix were not changed.

| Check | Result |
| --- | --- |
| `composer check` | Passed: 698 tests, 2,161 assertions; lint/platform, both PHPStan lanes, coding standards, API manifest, docs, examples, release consistency, repository verification passed. |
| Line coverage | Passed: 95.75% overall; 97.00% compiler. |
| Branch coverage | Passed: 92.46% overall; 92.04% compiler. |
| SQLite behavior/execution/transaction probes | Passed on SQLite 3.45.1; not a new minimum-runtime qualification. |

The synthetic evidence cases cover MariaDB/MySQL codes `1040`, `1045`, `2002`,
`2003`, `2006`, `2013`, and `4031` with integer and string driver codes,
missing `errorInfo`, empty and non-scalar entries, and an integer exception
code fallback. A live SQLite construction failure confirms the end-to-end path
(SQLSTATE `HY000`, SQLite code `14`) without exposing the DSN path, and a
driver/DSN mismatch confirms that configuration rejection stays a
`ConfigurationException` instead of becoming a connection failure.

Redaction checks assert the fixed safe construction message, absent DSN/path
and driver text, a null previous exception, and `#[SensitiveParameter]` on the
DSN, username, and password parameters. Query execution redaction tests were
preserved. The public manifest diff was reviewed: one DSN attribute, five
`ConnectionException` properties, one constructor, and three static factories
were added.

## Limits and remaining work

- No live authentication/capacity construction failure was executed against
  the disposable direct engines in this run; W1's direct lifecycle reports
  remain the latest direct-engine qualification and already include an
  intentionally rejected connection attempt. The synthetic shapes are the W2
  contract coverage.
- The direct/proxy service matrix was not rerun because W2 changes no
  engine-facing SQL, session, or transaction behavior. Proxy idle-recovery and
  replay policy remain W6 qualification.
- Consumer error-handler, logging, and HTTP response redaction verification and
  the real FrankenPHP worker rehearsal remain consumer/W3–W6 work. The library
  documents the boundary; it cannot prove consumer logging behavior.
- `QueryExecutionException` still retains the previous `PDOException`, whose
  message and trace may contain sensitive lower-level diagnostics. That
  accepted trade-off is unchanged and documented.
