## Security review

The changed input paths keep identifiers, bound values, structured expressions,
and trusted raw SQL distinct. Column positions now reject aliased and wildcard
identifier objects; raw expressions remain an explicit trusted-code path.
Bindings stay parameterized and ordered, generated IDs are read from the same
execution connection, and no retry or replay path was added. Optional affected-
row observation failures cannot replace a successful insert result. The
focused validation, binding-order, observation, and resource-ownership tests
passed in the full suite.

Generated reports remain in ignored `coverage/`, `build/package-check/`,
`tools/database-probes/results/`, and `benchmarks/results/` directories. They
are local records for this source revision, not hosted CI artifacts.
