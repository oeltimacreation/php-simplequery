## Security and architecture review

The complete `v0.2.0..d96ad31` source delta, public manifest, ADR-019, ADR-020,
compiler tests, cursor/transaction failure tests, and probe results were
reviewed against the maintainer security checklist.

| Area | Outcome |
| --- | --- |
| Identifier/value/raw boundary | Accepted expression overloads require an explicit `RawExpression`; strings keep identifier/value roles, values use `Binding`, operators use the closed allowlist, and two-raw-operand joins remain rejected. |
| Binding order | Expression-owned bindings compile before comparison bindings; nested groups, joins, subqueries, projections, and `HAVING` are covered across every dialect and live engine. |
| Dynamic input and diagnostics | Dynamic identifiers remain application-allowlisted. Exceptions and observation retain placeholder SQL and structured driver evidence without values, credentials, or executable debug SQL. |
| Generated IDs and replay | `lastInsertId()` remains captured immediately on the executing PDO. No reconnect, statement replay, transaction retry, or retryability classifier was added. |
| Transaction ownership | Managed begin now verifies physical activity before callback work. External work is not adopted, savepoint names remain internal, and SQLite immediate work remains explicitly application-owned. |
| Cursors and connection state | Early cursor cleanup is executable documentation; live cursors cannot cross completion silently, and uncertain cleanup/control state quarantines the connection. |
| Public/extension surface | The reviewed manifest contains only the accepted expression and column overloads. AST, compiler, executor, and transaction implementations remain closed `@internal` seams. |

No correctness, security, binding-order, cursor-lifetime, transaction-state, or
architecture blocker was found in the candidate.
