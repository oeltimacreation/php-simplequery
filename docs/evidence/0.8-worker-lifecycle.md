# 0.8 worker lifecycle and session hygiene validation

Date: 2026-09-18. Scope: W3 library example, documentation, and direct-engine
probe qualification, not a release certification, production deployment claim,
or FrankenPHP worker qualification.

## Source and accepted contract

The tested candidate consists of commits `7539619` (framework-free worker
request lifecycle example and example wiring), `330e2b8` (direct session-hygiene
probe and service-runner integration), and `b20829c` (worker, transaction,
observability, and upgrade documentation). The recorded decisions are
[ADR-024](../adr/024-explicit-connection-lifecycle.md) for the explicit
lifecycle surface and the W3 OBS-1 decision below; no new public API, ADR, or
support claim is introduced.

W3 keeps the accepted W1/W2 contract: one execution unit owns its connection,
models, builders, and cursors; replacement belongs to an application-owned
factory at a unit boundary; initialization is reapplied before a new connection
is published; temporary session changes are restored in `finally`; and an
uncertain failure retires the affected role without reconnect or replay.

The library adds no lifecycle observer. The OBS-1 decision keeps bounded
lifecycle counters application-owned and documents that query observation does
not cover connection events, direct PDO statements, transaction controls, or
delayed cursor fetches. Adding a lifecycle observer later requires a
demonstrated need and an ADR-010 amendment.

## Reproduction

From a development checkout with dependencies and PDO extensions installed:

```bash
composer check
composer test:coverage
composer coverage:check
composer test:coverage:branch
composer coverage:check:branch
composer probe:sqlite
composer probe:execution -- sqlite
composer probe:transaction -- sqlite
composer examples:check
php tools/database-probes/session-hygiene.php mariadb
php tools/database-probes/session-hygiene.php mysql
bash tools/database-probes/run-services.sh
```

The example is framework-free and uses SQLite in memory; it is executed by
`composer examples:check`. The service runner starts disposable fixtures, runs
the existing behavior/execution/transaction/lifecycle regressions plus the new
session-hygiene probe, records image digests/proxy versions, and removes its
containers/network/volumes. Use `PROBE_EMULATE_PREPARES=true|false` and
`PROBE_BUFFERED=true|false` to select profiles. Generated output remains
ignored under `tools/database-probes/results/`. The session probe creates only a
synthetic throwaway table, changes only its own session settings, and never
changes production or global configuration.

## Results

Local PHP was 8.4.24 with mysqlnd 8.4.24. Line coverage used PCOV 1.0.12;
branch coverage used Xdebug 3.5.3. The package's PHP 8.2 compatibility floor
and declared engine support matrix were not changed.

| Line coverage | Passed: 95.75% overall; 97.00% compiler. |
| Branch coverage | Passed: 92.46% overall; 92.04% compiler. |

| New direct session-hygiene probe | Eight reports; each passed 16 observations with two (MariaDB) or three (MySQL) additional observations. |

The example asserts cache-only requests open no connection, warm reuse keeps
one session, the monotonic idle threshold replaces only at a unit boundary, a
mid-unit threshold advance does not swap the pinned owner, two lazily resolved
models share the transaction owner, primary eviction leaves the read role
untouched, tracked cursors close before reuse, untracked cursors force a
discard, early returns and thrown `Throwable` still clean up, handled errors
evict, session initialization is reapplied after every replacement, report
settings are restored on success and failure, restoration failure preserves the
original exception, and shutdown opens nothing.

The probe verifies initialized values, session-scoped limits, restoration,
replacement reinitialization, documented idle/lock inputs, observation
boundaries, and acquisition cost on live disposable fixtures:

| Observation | MariaDB 11.8.8 | MySQL 8.0.46 |
| --- | --- | --- |
| Statement limit | `max_statement_time`, seconds | `max_execution_time`, milliseconds |
| `SELECT` limit evidence | `70100` / `1969` | `HY000` / `3024` |
| Non-`SELECT` scope | `UPDATE ... WHERE SLEEP(...)` bounded (`1969`) | `DO SLEEP(0.6)` completed in ~600.6 ms under a 100 ms limit |
| Session idle input | `wait_timeout=28800`, `innodb_lock_wait_timeout=50` | `wait_timeout=28800`, `innodb_lock_wait_timeout=50` |
| Acquisition + initialization | 588.5 µs min / 630.2 µs median / 750.7 µs max (five samples, native/buffered) | 709.8 µs min / 811.8 µs median / 928.5 µs max (five samples, native/buffered) |

The acquisition figures are a single-profile observation on a local disposable
fixture, not a benchmark comparison or a performance commitment. They confirm
that measurement is possible without a per-query ping.

The probe statement shape matters: under MySQL unbuffered profiles a bare
`SELECT SLEEP(...) FROM table` surfaced as a truncated result instead of a
timeout error, while `SELECT COUNT(*) ... WHERE SLEEP(...) = 0` failed
deterministically in all four profiles. Timeout evidence shape is not portable;
assert on the observed engine evidence rather than a single expected pattern.

Session initialization is per session: raising the limit in one session did not
change the second session, and after a simulated restoration failure the
replacement session required initialization again. Observation checks confirm
that `isReusable()` emits no event, direct `PDO::exec()` session commands are
unobserved, builder session commands are observed exactly once, and transaction
control is not observed.

## Limits and remaining work

- This run does not execute FrankenPHP/ZTS request loops, a one-hour worker
  soak, or the private consumer. The W6 rehearsal with pinned PHP/PDO/
  FrankenPHP/engine versions and a classic-mode control remains open. The
  SQLite example and probes are not a worker qualification.
- The session probe runs against direct MariaDB and MySQL only. Proxy session
  stickiness, session-command handling, and replay policy remain their own W6
  qualification and are not inferred from the direct engines.
- Consumer request cleanup, timeout restoration, error-handler redaction, and
  static-analysis adoption remain W4/W6 work. The library documents and tests
  the application-owned boundary; it cannot prove consumer wiring.
- No public API, support floor, or engine/proxy claim changes. `isReusable()`
  remains a local check, not a ping or session-cleanliness proof, and no
  automatic reconnect, retry, or lifecycle observer was added.
