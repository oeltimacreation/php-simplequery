# 0.8.1 cursor guard cost correction

Date: 2026-09-18. Scope: the post-release correction for the per-row cursor
discarded-connection guard cost observed after `0.8.0` publication.

## Observed regression

`0.8.0` added a per-row discarded-connection guard to cursor iteration: before
every fetch, `Cursor::rows` called `Connection::isClosed()` and threw
`ConnectionException::closed` when the wrapper had been discarded. The guard
preserves the documented "advanced after discard fails before another fetch"
behavior, but it added two method dispatches per row.

The `v0.8.0` tag CI benchmark comparison
([run 35351327099](https://github.com/oeltimacreation/php-simplequery/actions/runs/35351327099))
reported repeatable candidate costs on streaming-cursor operations. The first
attempt blocked `cursor_exhaustion/simplequery_object_cursor`
(+0.044 ms, 9.4%) and `result_memory_normal/simplequery_streaming_cursor`
(+0.062 ms, 9.0%); a rerun blocked
`result_memory_high/simplequery_streaming_cursor`
(+0.87 ms, 8.8%). The same source tree passed three candidate runs, the
default-branch run, CodeScene, and the tag proxy matrix; the tag runs had
narrower identical-source ranges, so the small systematic cost blocked.

Local A/B measurement on `e171c1d` with and without the per-row guard
confirmed the attribution: `cursor_exhaustion/simplequery_object_cursor`
0.4306 ms vs 0.4068 ms and
`result_memory_normal/simplequery_streaming_cursor` 0.5755 ms vs 0.5402 ms
(means of three rounds).

## Correction

The wrapper lifecycle state now lives in an internal shared value object,
`Oeltima\SimpleQuery\Internal\ConnectionState`:

- `Connection` owns one `ConnectionState` and keeps `closed` there as the
  single source of truth; `@internal connectionState()` exposes it.
- `Cursor` captures the state at construction and checks
  `$this->state->closed` inline before each fetch; the failure is still
  `ConnectionException::closed` with `operation: closed`.
- The reviewed public API manifest records the `@internal` accessor as
  `compatibility: internal`; no public signature changes.

No other behavior changes. The focused
`CursorFailureTest::testDiscardBlocksFurtherFetches` cases and the complete
`composer check` gate pass.

## Measured effect

Alternating runs against the immutable `v0.8.0` worktree, three rounds of 15
samples after three warm-ups, median of medians:

| Operation | `v0.8.0` | Fixed | Improvement |
| --- | --- | --- | --- |
| `cursor_exhaustion/simplequery_object_cursor` | 0.4299 ms | 0.4074 ms | 0.0225 ms (5.2%) |
| `result_memory_normal/simplequery_streaming_cursor` | 0.5695 ms | 0.5441 ms | 0.0254 ms (4.5%) |
| `result_memory_high/simplequery_streaming_cursor` | 5.5267 ms | 5.3165 ms | 0.2102 ms (3.8%) |

The fixed medians match the earlier no-guard measurements (0.4068 ms and
0.5402 ms), so the single property read effectively removes the guard's
per-row cost.
