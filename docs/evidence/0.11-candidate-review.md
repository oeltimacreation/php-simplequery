# 0.11.0 candidate and release review

Local qualification on 2026-11-21 used the feature revision
`78e51d0787509e4ca0556cd74f2f26de158753ca`. The benchmark baseline is
`v0.10.0` at `450bb9b2ff81dfc3ddd733c13be865702439b492`. The candidate targets
`0.11.0` with a PHP 8.2 floor and the existing MariaDB 11.8, MySQL 8.0, and
SQLite 3.39.2+ fixtures.
[Upgrade guide](../guides/upgrading.md#upgrading-from-010-to-011)

## Scope and migration

- PHP 8.6 qualification adds coverage for SQLite, direct MariaDB/MySQL PDO
  behavior, and archive-installed consumers. Input validation uses an
  explicit trim character set for comparison operators and empty SQL.
- Structured existence predicates cover correlated read filters and nested
  `WHERE` groups. Validation rejects foreign connections, locked or paginated
  children, and use in `HAVING` or writes. [ADR-027](../adr/027-structured-exists.md) ·
  [Engine evaluation](0.11-structured-exists.md)
- Compiler allocation reductions cover the first binding list in a statement
  and immutable condition terms during cloning and detached snapshots.

## Benchmarks and SQL boundary review

Both benchmark source orders against `v0.10.0` passed correctness parity and
the paired regression gate with fresh noise controls. The four reference soak
scenarios passed. The prepared 5,000-value `IN` case reduced peak temporary
allocation from 168,168 to 32,944 bytes. The deep snapshot and compile case
reduced it from 17,712 to 11,576 bytes. The measured timing differences in the
allocation investigations were within the applicable noise limits. Candidate
reports are under `benchmarks/results/0.11-structured-exists.hmpHx7/`.
[Benchmark method](../maintainers/benchmarking.md)

The review followed values from child projection and predicates into positional
bindings and checked exact SQL and typed binding order across all three
compilers. Rejected attachment preserves parent state. Structured occurrences
carried through `IN` and derived sources fail write validation before PDO
execution. Raw SQL remains caller-owned and the feature adds no transaction or
connection ownership mechanism. [SQL input boundaries](../adr/004-sql-input-boundaries.md) ·
[Security review checklist](../maintainers/security-review-checklist.md)

## Hosted candidate verification

The final candidate `2e6947f9eb430b3f69886491c0ddaddf4b9edd7a` passed all 15
jobs in [CI run 44843865781](https://github.com/oeltimacreation/php-simplequery/actions/runs/44843865781).
The jobs covered PHP 8.2 through 8.6, lowest dependencies on PHP 8.2, actual
SQLite 3.39.2, minimum and current direct engines, no-dev artifact consumers,
the quality suite, and the benchmark comparison. The paired benchmark reports
showed no repeatable candidate-operation regression. Coverage was 96.95% overall
and 97.42% for compiler lines, and 93.01% overall and 93.21% for compiler branches.

The [proxy workflow](https://github.com/oeltimacreation/php-simplequery/actions/runs/45557529284)
passed the maintained ProxySQL and MaxScale matrix and soak benchmarks on the
same source. [CodeScene](https://codescene.io/projects/83012/delta/results/8530079)
approved the candidate after the structured predicate validation refactor.

The clean Composer and Git archives and the contaminated-source archive passed
their independent no-dev consumers. All 193 files and 740,842 uncompressed
bytes in the hosted ZIP matched the local Git archive, and the hosted ZIP passed
its own installed consumer. Its SHA-256 was
`2b3a92e6f2cebe834f0e5658db0715eb088cbb1d6fe3ee7c6aeea4c51c9163c1`.
