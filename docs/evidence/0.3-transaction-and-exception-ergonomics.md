# `0.3.0` transaction and exception ergonomics

Collected: 2026-07-28

Decision: convert ordinary atomic write groups to managed callbacks, reject a
public SQLite immediate mode after compatibility probing, and keep immediate
control and error classification application-owned.

## Manual transaction classification

The anonymized production review and synthetic corpus separate the nine manual
transaction-control candidates into behavior classes rather than treating
every direct PDO call as migration residue.

| Class | Managed disposition | Reason |
| --- | --- | --- |
| Ordinary atomic write group | Convert to `Connection::transaction()` | The callback owns the complete unit and existing rollback/savepoint behavior is sufficient. |
| MySQL/MariaDB row lock | Use an ordinary managed callback with typed `forUpdate()` / `forShare()` | Lock lifetime matches the managed outer scope; no new mode is needed. |
| SQLite immediate writer test | Keep application/PDO-owned | PHP 8.2/8.3 do not expose manual immediate begin through `PDO::inTransaction()`, so managed ownership cannot be proven across the runtime floor. |
| Schema or migration control | Keep application/PDO-owned | MySQL-family DDL can implicitly commit and invalidate ownership guards. |
| Deliberately external ownership | Keep application/PDO-owned | SimpleQuery must not adopt, complete, or relabel an existing unit of work. |

The synthetic adoption fixture now includes an ordinary managed write group,
immediate generated-ID capture, nested savepoints, callback exception identity,
active-cursor refusal, the SQLite immediate escape path, and deliberate
external ownership. The existing SQLite transaction integration suite executes
the ordinary managed cases.

## SQLite immediate probe

The transaction smoke uses a temporary file database and two independent
connections. For every supported PHP/SQLite compatibility job it verifies:

1. whether `BEGIN IMMEDIATE` makes `PDO::inTransaction()` true;
2. savepoint create, rollback, and release behavior inside the immediate scope;
3. a second immediate writer fails with SQLSTATE `HY000` and SQLite code `5`;
4. rollback succeeds through PDO when the transaction is tracked and through
   fixed control SQL when it is not;
5. the second connection can begin, write, and commit after the first releases
   writer ownership;
6. both connections are reusable with inactive physical state.

PHP 8.2 and 8.3 execute manual `BEGIN IMMEDIATE` while reporting
`inTransaction() === false`; PHP 8.4 and 8.5 report it as active. That split
rejects the managed-mode spike because the manager cannot preserve one
ownership-verification contract across the supported floor. Generated JSON
reports remain CI artifacts so exact PHP and linked SQLite versions accompany
each observation.

Applications retaining the escape path must issue fixed trusted control SQL,
choose completion according to their tested runtime, and never enter a managed
`Connection::transaction()` while the manual scope is active. On runtimes that
report false, SimpleQuery cannot detect or reject that external ownership.

## Exception inspection

`QueryExecutionException` already exposes the necessary evidence: `driver`,
`sqlState`, `driverCode`, placeholder SQL, connection label, and the previous
`PDOException`. Synthetic tests preserve representative deadlock, lock-timeout,
SQLite busy/locked, constraint, and transport values, including integer and
string driver codes. Live execution probes exercise constraint conversion and
SQLite busy contention.

A library classifier is rejected. SQLSTATE `HY000` covers unrelated lock,
transport, and general errors; code meanings depend on the selected driver;
deadlock and lock-timeout outcomes do not prove callback replay is safe; and a
commit failure can remain ambiguous regardless of its code. Applications may
classify evidence for logging or a bounded, operation-specific policy, but the
library does not label failures retryable.

## Application-owned recipe

Normalize the driver code to a string and branch on both the declared driver
and the SQLSTATE where it adds useful discrimination:

```php
use Oeltima\SimpleQuery\Driver;
use Oeltima\SimpleQuery\Exception\QueryExecutionException;

function isLockConflict(QueryExecutionException $exception): bool
{
    $code = (string) $exception->driverCode;

    return match ($exception->driver) {
        Driver::MariaDb, Driver::MySql => in_array($code, ['1205', '1213'], true),
        Driver::Sqlite => $exception->sqlState === 'HY000'
            && in_array($code, ['5', '6'], true),
    };
}
```

This is an inspection recipe, not a retry guarantee. A caller considering
replay must separately bound attempts, prove callback side effects idempotent,
exclude ambiguous commit outcomes, and discard quarantined connections.

## Scope conclusion

Phase 3 adds no transaction mode and no exception classifier. It strengthens
managed begin verification and preserves the accepted ownership gate: no
external transaction is adopted, no ambiguous commit is hidden, and no
operation is described as safe to retry. ADR-020 records the rejected mode;
ADR-008 and ADR-009 continue to own transaction and exception evidence
semantics.
