# `0.4.0` contract freeze

Status: accepted 2026-08-01 (SQ-0404).

This record locks the `0.4.0` release scope at the frozen `v0.3.0` public
contract. It is the durable reference for the phase gates and the release-level
definition of done in the `0.4.0` development plan.

## Zero-change pledge

`0.4.0` introduces zero breaking changes and zero new public API methods,
constants, classes, or signature changes beyond the frozen `0.3.0` contract.
The public API signature manifest
(`tests/Fixtures/Contracts/public-api.json`) is byte-identical to `v0.3.0` and
remains enforced by `composer public-api:check` on every quality gate.

Consequences:

- compiled SQL, positional binding order, exception classes and messages, and
  raw-expression safety boundaries are preserved exactly by every refactor;
- internal AST, compiler, executor, and transaction classes stay closed
  `@internal` (ADR-003, ADR-013); a refactor that changes the manifest is a
  defect by default unless a proven bug requires it and this plan is revised
  with an ADR;
- feature work that would change the public surface is deferred to `0.5.x`
  (see [Deferred feature backlog](#deferred-feature-backlog)).

## Deferred feature backlog

Each deferred item returns only with a synthetic use case, exact SQL and
binding expectations, failure semantics, all-engine behavior or an explicit
engine boundary, and a maintenance-cost assessment:

- structured subquery existence predicates (`whereExists()`, `orWhereExists()`,
  `whereNotExists()`, `orWhereNotExists()`);
- fluent conditional query branching (`when()`, `unless()`) and pagination
  helpers (`forPage()`);
- scalar and column-list terminals (`value()`, `pluck()`) and memory-bounded
  chunking (`chunk()`, `chunkById()`);
- `whereBetween()` trusted-expression operand overloads and standardized
  subquery comparison operands in `where()`;
- non-recursive CTE (`WITH`) compilation and its ADR;
- SQL inspection helpers (`toSql()`, `explain()`) and the optional consumer
  PHPStan raw-interpolation rule.

The full rationale was recorded in the completed 0.4 development plan under
"Deferred scope" and "Explicit non-goals". The plan was retired when 0.5
planning began; this evidence record preserves the historical decision.

## Compilation hot-path allocation targets

The following are target-observation points, not new APIs. Baselines and
decision rules are recorded in the
[`v0.3.0` development baseline](v0.3.0-development-baseline.md) and the
[duplication and complexity inventory](0.4-duplication-and-complexity-inventory.md):

1. `QueryState::copy()` should become lazy where safe so `first()`/`count()`/
   aggregate terminals do not deep-copy the full AST on every terminal call.
2. `CompilationContext` should be reused instead of re-created per
   `compile()`.
3. Repeated `InputNormalizer` work and per-`compile()` compiler allocation
   (`CompilerFactory::for()`) should be avoided without shared mutable state.
4. The paired `v0.3.0` comparison is the regression gate: no median
   compilation/execution regression greater than 5% is accepted without
   evidence and a plan revision.

## Acceptance

The freeze is accepted when the public API manifest digest in the
[`v0.3.0` development baseline](v0.3.0-development-baseline.json) is unchanged
and every inventory hotspot is resolved or explicitly accepted against the
rules in [the inventory](0.4-duplication-and-complexity-inventory.md).
