## Implemented scope and contracts

The candidate contains five focused implementation commits, each with its
tests and documentation:

| Commit | Result |
| --- | --- |
| `3d20e3d` | Executor cleanup remains responsible for a failed cursor attempt until successful handoff. Primary bind/execute failures survive cleanup failure. |
| `fde448b` | Structured children with row locks are rejected before derived-source or `IN`/`NOT IN` attachment. Ordinary snapshots and ordered bindings are preserved. |
| `cf28ac7` | Failed mandatory lock-state inspection captures managed depth, throws structured transaction-state evidence, and quarantines the owner without completion SQL. |
| `39b961e` | Failed optional transaction-depth inspection still delivers the notification with `transactionDepth=null`, preserving the original result/failure. |
| `fbe2ab3` | Untyped `when()`/`unless()` callback parameters infer the existing builder type; runtime callback behavior is unchanged. |

The recommended D1 rejection policy is accepted in
[ADR-026](../adr/026-locked-child-queries.md). D2's nullable public observation
depth is accepted in [ADR-010](../adr/010-non-interfering-observation.md).
[ADR-006](../adr/006-results-and-write-returns.md) clarifies cursor ownership and
[ADR-008](../adr/008-transaction-ownership-and-savepoints.md) records mandatory
lock inspection. The reviewed API-manifest changes are one internal child
compilation seam, the nullable observation constructor/property, and two callback
annotations. The [upgrade guide](../guides/upgrading.md) covers migration impact.
Completed changes remain under `[Unreleased]`.

Strict-close propagation, partial multi-column clause mutation, caller-owned
LOB streams, logical aggregate semantics, generated-ID timing, owner pinning,
and transaction control counts retain their existing policies. No engine/floor,
retry, reconnect, routing, framework, or public compiler-plugin contract is added.

## Runtime and minimum checks

PHP 8.4.27 and PHP 8.5.12 use local PDO SQLite 3.46.1. Isolated Bookworm images
were built for PHP 8.2.35 and PHP 8.3.36 with `pdo_mysql`; their default PDO SQLite
runtime is 3.40.1. Both ran 968 tests and 3,696 assertions successfully, with one
class-level skip for unavailable ZIP tooling. That tooling is covered by the
complete host suite and independent package certification below. The local
PHP 8.3 CLI's missing SQLite driver was not treated as a compatibility pass.

The runtime image recipe was `FROM php:<version>-cli-bookworm` followed by
`RUN docker-php-ext-install pdo_mysql`. Resolved base-image digests were:

| Runtime | Base image digest |
| --- | --- |
| PHP 8.2.35 | `sha256:58bd7cb60b690c01106084ce4a0a73eb01094ceb00904ebb4b8514516765292a` |
| PHP 8.3.36 | `sha256:cdb77e306d6bb99db40e513fbe036ecc6c53b575cbcb7e581387845fef26d755` |

The lowest-dependency lane used an isolated detached worktree at the tested
commit, `composer update --prefer-lowest --prefer-stable --no-interaction
--prefer-dist --no-progress`, and the PHP 8.2.35 image. PHPUnit 11.5.50 ran the
same 968 tests / 3,696 assertions with the same ZIP-tooling skip. The main
checkout's lock file was not modified.

Actual PDO SQLite 3.39.2 passed 53 integration tests and 289 assertions plus the
maintained behavior, execution, and transaction probes. The host's newly built
PHP 8.5 PDO extension requires `sqlite3_stmt_explain`, which that older library
does not provide, so the host attempt could not load its SQLite extensions.
The maintained minimum runner was instead executed successfully inside the
PHP 8.2.35 image, compiling the checksum-pinned SQLite source there.

To reproduce that minimum run after building the image:

```bash
mkdir -p build/sqlite-minimum .phpunit.cache tools/database-probes/results
docker run --rm --user "$(id -u):$(id -g)" \
  --volume "$PWD:/app:ro" \
  --volume "$PWD/tools/database-probes/results:/app/tools/database-probes/results" \
  --tmpfs /app/build/sqlite-minimum:rw,exec,mode=1777 \
  --tmpfs /app/.phpunit.cache:mode=1777 \
  --workdir /app simplequery-candidate-php:8.2 \
  bash tools/database-probes/run-minimum-sqlite.sh
```

The temporary executable build mount prevents reuse of an incompatible host
library. It does not change the declared SQLite floor or replace actual
minimum execution with a version-return double.
