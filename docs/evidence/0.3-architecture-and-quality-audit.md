# `0.3.0` architecture and quality audit

Status: accepted Phase 4 evidence.

This audit reviews only the library's synthetic public repository. It contains
no consumer source, private paths, credentials, DSNs, hostnames, customer data,
or proprietary SQL.

## Public signature control

The reviewed manifest at
[`tests/Fixtures/Contracts/public-api.json`](../../tests/Fixtures/Contracts/public-api.json)
is generated from the runtime reflection surface by `composer
public-api:update`. `composer public-api:check` regenerates it in memory and
fails when the checked-in record differs. The manifest records public classes,
interfaces, enums and cases, inheritance, final/abstract/readonly status,
public constants and properties, method modifiers, parameter types/defaults
and attributes, return types, and relevant PHPDoc generic annotations.

Declarations below `Oeltima\SimpleQuery\Internal` are excluded. Public methods
marked `@internal` remain in the manifest with `compatibility: internal`, so a
change cannot bypass review merely because it is outside the compatibility
promise. An intentional public change requires implementation evidence, user
documentation, changelog and upgrade guidance, then an explicit manifest
refresh in the same review.

## `@internal` seam audit

PHP has no package-private or friend visibility. The following public
visibility is therefore retained for closed collaboration between final
library classes:

- construction: `ConditionGroup`, `JoinClause`, `QueryBuilder`, and `RawQuery`
  constructors; `Cursor::objects()` and `Cursor::associative()`;
- compilation: `Connection::forCompilation()`, the three `QueryBuilder`
  compilation/ownership accessors, and condition/join snapshots;
- execution and state: the connection's executor PDO/observer accessors,
  cursor register/release operations, quarantine operation, transaction depth,
  active-cursor query, and row-lock transaction guard.

Every seam is explicitly marked `@internal`. Moving these methods into one
public context object was rejected: it would add an authority-bearing object,
broaden access to unrelated operations, and create another collaboration to
maintain without reducing public PHP visibility. Closure-based access was also
rejected because it obscures ownership and static-analysis types. The current
small, purpose-named methods keep state mutation on `Connection` and keep all
participating classes final.

## Responsibility hotspots and extraction decisions

| Hotspot | Finding | Decision |
| --- | --- | --- |
| `TransactionManager` | Large, but its depth, ownership guard, recovery and quarantine transitions form one state machine. | Retain intact; splitting completion paths would distribute invariants and exception evidence. |
| `AbstractDialectCompiler` | SQL assembly is broad but ordered binding composition is centralized; predicate helpers were already narrowed during Phase 2. | Retain the closed dialect template; no new public or internal strategy seam. |
| `QueryBuilder` | Many methods reflect the deliberate fluent surface; normalization, condition construction, compilation and execution are already delegated. | Retain as the mutable query-definition façade. |
| `Connection` | Construction policy and per-PDO lifecycle state meet at the execution-unit owner. | Retain ownership together; extracting state would permit invalid independent lifetimes. |
| `Executor` | `getAssociative()` and `firstAssociative()` duplicated associative row/key validation. | Reuse the existing private validator for both terminals. This is the only evidence-backed extraction. |
| `Cursor` | Iteration, statement cleanup, cursor registration and quarantine are one lifecycle. | Retain together; cleanup failure must atomically release tracking and quarantine. |

The executor change is private, preserves SQL, binding order, exception
translation and result shapes, and is covered by full/first associative result
tests. No public signature or benchmark scenario changes.

## Static analysis and style audit

The independent PHPStan level-9 fixture now includes a synthetic repository
constructor, mutable builder-returning helper, raw-expression comparison,
condition and join callbacks, generated ID capture, managed transaction return
inference, generic cursor rows, and SQLSTATE/driver-code inspection. It is
relative to the repository configuration and contains no environment-specific
path.

The existing PSR-12/Slevomat rules already enforce strict types, unused
imports, dead catches, useless variables and useless ternaries. The audit added
only three zero-baseline rules that pass the current tree: disallow grouped
imports, require one import per statement, and disallow Yoda comparisons. More
opinionated early-return, declaration-order and docblock rules were rejected as
high-churn without demonstrated defect prevention.

## High-risk behavior evidence

Focused additions cover ambiguous condition and join operand counts/types,
transaction-state inspection failure and quarantine, absent PDO error evidence,
second cursor iteration, and connection close while a cursor remains active.
Existing branch tests continue to cover callback/control/recovery exception
identity, cursor cleanup failure, connection reuse/quarantine, binding order and
non-mutation. The established coverage floors remain unchanged.

Relative Markdown link validation is dependency-free, scans root and `docs/`
Markdown, ignores external/absolute/fragment-only links and generated output,
and is part of `composer check`. Its tests cover valid fragments, external
links, missing targets and an ignored generated coverage tree.
