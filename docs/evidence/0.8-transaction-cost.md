# 0.8 transaction cost validation

Date: 2026-09-18. Scope: W5 measurement of managed transaction control cost and
the D5 decision, not a release certification or a performance promise.

## Tested source

- Candidate: `feature/0.8-candidate` at `88eb2e1`.
- Baseline: immutable `v0.7.0` (`a335eb1`) in a detached worktree with its own
  runtime autoloader.
- Direct engines: MariaDB 11.8.8 and MySQL 8.0.46 disposable fixtures.
- Proxies: ProxySQL 3.0.1 and MaxScale 23.02.17-2 disposable fixtures.
- Local PHP 8.4.24; the benchmark comparison used 3 warm-ups and 9 samples per
  operation in both source orders with the identical-source noise control.

## Method

1. **Controlled PDO call counts.** `TransactionControlSequenceTest` asserts the
   exact control SQL and completion calls, and `CountingPdo` records the same
   shape on live engines: begin, savepoint, release, rollback-to-savepoint,
   commit, rollback, plus `inTransaction()` inspections.
2. **Direct-engine component probe.** `tools/database-probes/transaction-cost.php`
   runs raw-PDO controls (noop, write, savepoint write), managed noop/write,
   nested noop/write/failure, rollback, connection acquisition, and session
   initialization. Each operation is correctness-checked and reports median and
   p95 microseconds over 200 samples after 20 warm-ups, with exact control
   counts for the measured window.
3. **Maintained benchmark comparison.** The CI suite runs `benchmarks/compare.php`
   against the `v0.7.0` worktree with the identical-source noise control and
   both source orders, matching the [benchmark method](../maintainers/benchmarking.md).
4. **Proxy pass-through.** The same control assertions run through ProxySQL and
   MaxScale in native/emulated and buffered/unbuffered profiles.

## Control sequences

The root managed transaction issues exactly:

1. `beginTransaction()`;
2. `SAVEPOINT simplequery_root_N` (ownership guard);
3. `RELEASE SAVEPOINT simplequery_root_N` before commit (ownership check);
4. `commit()`.

Nested success adds `SAVEPOINT simplequery_nested_N` and its release. Nested
failure adds `ROLLBACK TO SAVEPOINT` followed by release before the outer
commit. Outer failure releases the root guard and rolls back. External
transactions are rejected before any managed control SQL, and a failed begin
issues no guard or completion SQL.

Live control counts were identical on both direct engines and both proxies in
every tested profile: a managed empty root transaction performed one
begin/savepoint/release/commit each, and a nested empty transaction performed
two savepoints and two releases. `inTransaction()` inspections were four per
root transaction and eight with one nested scope (client-side calls, no SQL).

## Component timing (local medians, median of three runs)

All values are microseconds on disposable local fixtures; they are attribution
evidence, not portable latency.

| Component | MariaDB 11.8.8 | MySQL 8.0.46 |
| --- | --- | --- |
| Raw `begin`/`commit` noop | 42–74 | 43 |
| Raw write with savepoint pair | 678–843 | 1,894–2,008 |
| Managed empty root transaction | 95–123 | 96–135 |
| Managed root insert | 918–979 | 2,036–2,038 |
| Managed nested empty scope | 145–153 | 150–206 |
| Managed nested failure (caught) | 204–206 | 222–355 |
| Managed rollback | 233–285 | 215–341 |
| Connection acquisition | 182–355 | 261–330 |
| Session initialization command | 55–71 | 56–58 |

The ownership guard plus inspections therefore add tens of microseconds per
root transaction at these scales, roughly 1.8–2.2× a bare `begin`/`commit` for
an empty transaction, and a similar absolute increment over a raw write with a
savepoint pair. Connection acquisition and session initialization are larger
per-unit costs than the guard.

## Maintained benchmark comparison

The paired comparison passed in both source orders with the identical-source
noise control (absolute floor 0.57 ms). The `transactions` scenario digest
matched between sources. Median measurements were:

| Order | Operation | v0.7.0 | Candidate | Review |
| --- | --- | --- | --- | --- |
| baseline-first | `simplequery_managed` | 0.174 ms | 0.073 ms | Within identical-source range |
| baseline-first | `pdo_control` | 0.027 ms | 0.049 ms | Direct-PDO control |
| candidate-first | `simplequery_managed` | 0.187 ms | 0.180 ms | Within identical-source range |
| candidate-first | `pdo_control` | 0.027 ms | 0.049 ms | Direct-PDO control |

All medians are below 1 ms and within the observed identical-source ranges or
on the direct-PDO control, so the comparison reported no repeatable
candidate-operation regression. The transaction manager's control shape is
otherwise unchanged from `v0.7.0`; the only source differences are the W1
lifecycle inspection accessor and a closed-wrapper ownership check.

## Proxy behavior

Savepoint creation, release, rollback-to-savepoint, commit, and rollback passed
through both ProxySQL and MaxScale in all four prepare/buffering profiles with
the same control counts. The proxies neither removed nor merged the ownership
guard.

## D5 decision

**Retain the ownership guard and inspection cost by default.** The guard pair
is what lets the manager detect an implicit commit or a replacement physical
transaction before it commits work it does not own; `inTransaction()` alone
cannot distinguish the original transaction from a replacement. The measured
absolute cost is tens of microseconds per transaction on direct engines, and no
equivalent check was demonstrated. Optional or profile-controlled guards are
declined for `0.8.0` because they would need a separate public opt-out contract
and equivalent failure evidence. Re-open only with measured consumer impact, an
equivalent ownership check, and an
[ADR-008](../adr/008-transaction-ownership-and-savepoints.md) amendment.

## Limits and remaining work

- Timing figures come from one busy local host and disposable fixtures; they
  are not a benchmark baseline or a capacity claim. The paired, noise-controlled
  comparison is the maintained regression gate.
- Proxy runs cover the disposable fixture configuration only; production proxy
  settings may differ and remain operator-owned.
- No transaction behavior, public API, support floor, or guard was changed.
