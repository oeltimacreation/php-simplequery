# `0.4.0` development plan

Status: Phase 0–4 complete; Phase 5 and Phase 6 planned

Target: the next minor release after `0.3.x`. No calendar date is promised.

## Release outcome

`0.4.0` is a quality, consolidation, and stability release. After `0.3.0`
delivered the adoption baseline, expression comparisons, and hardened
transaction and cursor semantics, `0.4.0` pays down structural debt before the
next feature increment:

1. **De-duplication.** Collapse repeated compiler, condition-construction, and
   test-double logic into single, verified implementations and data-driven
   test suites.
2. **Code quality.** Reduce complexity and magic-string risk, tighten type
   safety, modernize PHP 8.2+ usage, and fix latent correctness gaps.
3. **Performance and stability.** Cut compilation hot-path allocations and keep
   regression, stress, and memory bounds paired against the `v0.3.0` baseline.
4. **Documentation.** Overhaul the documentation tree so human readers and AI
   agents can navigate it reliably, with a single source of truth for the
   public API contract.

The release is intentionally feature-light: it adds **no new public API
surface** and introduces **zero breaking changes** to existing `0.3.0`
signatures. The feature work previously planned for `0.4.0` (structured
subquery predicates, conditional branching, result-set terminals, chunking,
and CTE compilation) is deferred to `0.5.x` under the criteria in
[Deferred scope](#deferred-scope). The release remains a query-builder release;
it will not absorb an ORM, schema/migration system, connection pool, retry
engine, or every SQL feature expressible through trusted raw SQL.

## Development baseline

SimpleQuery `0.3.0` established canonical query, transaction, streaming,
batching, migration, and API guidance, alongside baseline evidence across
SQLite, MariaDB 11.8, MySQL 8.0, ProxySQL, and MaxScale.

The current library profile contains:

| Observation | Count or result |
| --- | ---: |
| Core PHP source files in `src/` | 17 |
| AST, Compiler, Executor, Transaction internal modules | 4 |
| Public API classes and contracts in reflection manifest | 12 |
| Executable example scripts in `examples/` | 11 |
| Quality, compiler, unit, integration, and adoption test cases | 100% pass |
| Required line / branch / compiler coverage floors | 90% / 80% / 95% line (80%/90% branch) |

### What 0.3.0 accomplished

- Added trusted expression-to-bound-value comparisons
  (`where($raw, '=', $val)`), column-to-column predicates (`whereColumn`), and
  expression join conditions.
- Added explicit adoption audit tooling, a synthetic adoption corpus, and
  migration review reporting.
- Probed and documented SQLite immediate transaction limits (ADR-020) and
  application-owned retry/exception recipes without retry claims.
- Added a public API signature manifest, a relative documentation link
  checker, a PHPStan level 9 external consumer fixture, and a
  production-shaped performance harness.

### Why `0.4.0` is a quality release

The `0.3.0` evidence recorded healthy behavior but also exposed structural debt
that grows with every feature. The Phase 0 inventory of the `v0.3.0` tree
found the following hotspots:

| Hotspot | Location | Phase 0 observation |
| --- | --- | --- |
| MySQL-family compiler duplication | `src/Internal/Compiler/MariaDbCompiler.php`, `MySqlCompiler.php` | The two classes differ only in the shared-lock clause (`LOCK IN SHARE MODE` vs `FOR SHARE`); every other clause is inherited. |
| Dialect golden-write duplication | `tests/Compiler/{MariaDb,MySql,Sqlite}CompilerTest.php` | Near-identical insert/insertMany/update/delete golden assertions repeated per dialect with only quoting differing. |
| Test-double sprawl | `tests/Unit/{Controlled,ControlledAssociative,Throwing,ThrowingFetchAndClose,ExhaustingThrowingClose,FalseClose}Statement.php` | Seven `PDOStatement` subclasses whose fetch/close behavior could be one configurable double. |
| Condition-construction duplication | `QueryBuilder::addHaving()` vs `BuildsConditions::addCondition()` | Two private implementations of the same `ConditionFactory::condition()` dispatch; only negation handling differs. |
| `func_num_args()` overload dispatch | `BuildsConditions`, `ConditionFactory`, `QueryBuilder` | Magic argument-count dispatch for `where()`/`having()`/`join()` shapes; works but is brittle to analyze. |
| Magic strings in internal state | `LockState::$mode`, `LockState::$modifier`, `JoinState::$type` | `'update'/'share'`, `'NOWAIT'/'SKIP LOCKED'`, and `'INNER'/'LEFT'` flow as untyped strings through the AST. |
| Connection construction surface | `src/Connection.php` | 458 lines mixing lifecycle, DSN validation, PDO option merging, and supported-profile checks in one class. |
| Per-terminal allocation | `QueryState::copy()`, `CompilerFactory::for()`, `QueryBuilder::executor()` | `first()`/`count()`/aggregates deep-copy the AST; every `compile()` allocates a fresh compiler and every terminal a fresh executor. |
| Reference/evidence doc overlap | `docs/reference/public-api.md` vs `tests/Fixtures/Contracts/public-api.json`; `docs/maintainers/testing-strategy.md` vs `testing-architecture.md`; 18 evidence files | A manual reference mirrors a machine fixture; two testing documents overlap; retired plan and evidence content is not yet culled. |

These are consolidation opportunities, not defects: no reported correctness,
binding-order, or resource-safety problem exists in the `0.3.0` tree. Each
hotspot becomes an evidence-gated task whose acceptance is "identical
observable behavior, less code".

## Key focus for 0.4.0

1. **De-duplication.** Single verified implementations for repeated compiler,
   condition, write-compilation, connection-profile, and test-double logic.
2. **Code quality.** Lower complexity, replace magic dispatch and magic strings,
   tighten types, verify minimum-PHP-runtime compatibility, and prove the
   public/internal boundary stays closed.
3. **Performance and stability.** Reduce hot-path allocation, keep paired
   `v0.3.0` benchmarks, and extend SQLite lock-contention and memory-stability
   probes.
4. **Documentation.** A navigable, deduplicated documentation tree with a
   machine-checkable public API reference and AI-friendly structure.

## Priorities and decision rules

Priority order for `0.4.0`:

1. preserve exact SQL, positional binding order, exception types and messages,
   and raw-expression safety boundaries on every refactor;
2. de-duplicate before extending: a duplicate implementation is not a feature
   opportunity, it is the debt this release pays;
3. lower complexity and magic risk only with tests that pin current behavior;
4. reduce allocations only where the paired benchmark proves no regression;
5. make documentation a single-source-of-truth contract, not a mirror;
6. validate every phase against the frozen `v0.3.0` baseline before release.

A task enters implementation only when it has: the exact current behavior, the
expected post-refactor behavior, failure semantics, all-engine impact or an
explicit engine boundary, and a maintenance-cost assessment. Any refactor that
changes compiled SQL, binding order, exception class, or public signature is a
defect by default unless a proven bug requires it and this plan is revised with
an ADR.

## Phase 1 — Codebase de-duplication

Goal: remove repeated implementation logic with provably identical observable
behavior.

- [x] **SQ-0411 — Consolidate the MySQL-family compilers.** Extract the shared
  MySQL/MariaDB compilation into one base or strategy so only the lock clause
  differs; keep the closed `@internal` compiler boundary (ADR-003, ADR-013)
  intact. All golden SQL, bindings, and lock rejection tests must pass
  unchanged. Estimate: 2 days. Complexity: Medium.
- [x] **SQ-0412 — Unify condition-construction paths.** Merge
  `QueryBuilder::addHaving()` with the `BuildsConditions` condition path into
  one private dispatch shared by `where()`/`orWhere()`/`whereNot()`/`having()`
  groups, preserving null-predicate negation semantics exactly. Estimate:
  1.5 days. Complexity: High.
- [x] **SQ-0413 — Consolidate write compilation.** Deduplicate
  `insert()`/`insertMany()`/`update()`/`delete()` state validation and
  row/column compilation in `AbstractDialectCompiler` into shared private
  helpers, preserving exact validation order and error messages. Estimate:
  2 days. Complexity: Medium.
- [x] **SQ-0414 — Extract connection profile construction.** Move DSN
  validation, PDO option merging, and supported-profile checks out of
  `Connection` into one cohesive `@internal` profile class, keeping all
  construction, exception, and lifecycle tests green. Estimate: 2 days.
  Complexity: Medium.
- [x] **SQ-0415 — Remove dead and single-use indirection.** Delete confirmed
  dead code and collapse single-use internal abstractions from the inventory,
  each removal gated by a test that pins the removed behavior. Estimate:
  1 day. Complexity: Medium.

Gate: every dialect golden fixture compiles to identical SQL and bindings; all
exception classes and messages are unchanged; PHPStan level 9 and coverage
floors stay green.

## Deferred scope

The feature work previously planned for `0.4.0` is deferred to `0.5.x`. Each
item returns only with a synthetic use case, exact SQL and binding
expectations, failure semantics, all-engine behavior or an explicit engine
boundary, and a maintenance-cost assessment:

- structured subquery existence predicates (`whereExists()`, `orWhereExists()`,
  `whereNotExists()`, `orWhereNotExists()`);
- fluent conditional query branching (`when()`, `unless()`) and pagination
  helpers (`forPage()`);
- scalar and column-list terminals (`value()`, `pluck()`) and memory-bounded
  chunking (`chunk()`, `chunkById()`);
- `whereBetween()` trusted-expression operand overloads and standardized
  subquery comparison operands in `where()`;
- non-recursive CTE (`WITH`) compilation and its ADR;
- SQL inspection helpers (`toSql()`, `explain()`) and the optional consumer
  PHPStan raw-interpolation rule.

Deferral rationale: these features change the public API, and this release's
scope is to consolidate the existing surface first. Adding them now would
compound the very duplication, complexity, and documentation drift this plan
exists to remove.

## Explicit non-goals

Unless new evidence is added and this plan is revised before scope freeze,
`0.4.0` will not add:

- any new public API method, constant, class, or signature change beyond the
  frozen `0.3.0` contract (see [Deferred scope](#deferred-scope));
- an ORM, schema/migration API, identity map, relationship loader, or model
  base class;
- connection pooling, read/write replica routing, or global connection state;
- transparent reconnect, automatic query retry, or transaction replay;
- a public compiler, dialect, AST, or middleware plugin extension platform;
- named-placeholder support in the structured query builder;
- arbitrary object hydration or global mutable fetch modes;
- prepared-statement or builder-compilation caching across execution
  instances;
- restructuring that changes compiled SQL, binding order, exception class, or
  error message without a proven defect and a plan revision.

## Release-level definition of done

`0.4.0` is complete only when:

- all required phase gates pass and conditional rejections are documented;
- the public API manifest is byte-identical to `v0.3.0`;
- every refactor has a paired before/after behavior record showing identical
  SQL, bindings, exceptions, and results;
- the duplication gate passes and inventory hotspots are resolved or
  explicitly accepted;
- coverage floors (90% line / 80% branch overall, 95% line / 90% branch
  compiler) remain strictly enforced;
- paired `v0.3.0` comparisons show no unexplained regression > 5% and memory
  bounds are recorded;
- engine compatibility probes pass on SQLite 3.39.2+, MariaDB 11.8+, MySQL
  8.0, and MySQL 8.4 LTS;
- the documentation tree is deduplicated, machine-checked, and AI-indexed, and
  published guides describe only implemented behavior;
- the deferred feature backlog is recorded in this plan, not in reference
  docs.

Scope changes must be made here before implementation and include supporting
evidence, revised estimates, and updated gates. Published tags remain
immutable.
